# Приёмка Rust-экстрактора PDF

На Windows через `vsoft convert-result` прогнаны пять PDF в универсальном профиле. В каждой паре использовались один Rust-сборщик DXF, один AutoCAD Core Console 2024 и одинаковые настройки. Ветка сравнения запускалась с `VSOFT_PDF_EXTRACTOR=python`, новая ветка — с `VSOFT_PDF_EXTRACTOR=rust`. Папки для всех первичных прогонов были новыми. Во всех десяти DWG `AUDIT` без исправлений нашёл 0 ошибок. Контрольные суммы опубликованных файлов совпали с `complete.json`.

| Комплект | Листов | Статус в обеих ветках | Фрагменты PDF | Группы MTEXT, PyMuPDF → Rust | Прямые / кривые восстановлены | Замечания по пунктиру | Растровые вставки |
|---|---:|---|---:|---:|---:|---:|---:|
| ЩГА2 | 103 | `needs_review` | 21 817 | 289 → 297 | 1 553 / 0 | 358 | 104 |
| ПОГА | 18 | `needs_review` | 2 156 | 29 → 29 | 150 / 0 | 16 | 18 |
| ШС1 | 19 | `needs_review` | 3 890 | 46 → 46 | 1 063 / 92 | 499 | 0 |
| План цеха А2 | 1 | `ready` | 1 | 0 → 0 | 0 / 0 | 0 | 0 |
| Повёрнутый дробный CropBox | 1 | `needs_review` | 1 | 0 → 0 | 0 / 0 | 0 | 0 |

Счётчики фрагментов, восстановленных штрихов, замечаний и вставок совпали в обеих ветках. Для А2 и ШС1 использованы штатные `preview.pdf`. Для ЩГА2, ПОГА и дробного CropBox, где штатная печать отсутствует, напечатаны диагностические копии вкладок в масштабе 1:1 с другим размером бумаги. Эти копии использованы для сверки положения текста. Пакеты по-прежнему сообщают, что штатный формат печати недоступен.

Все начала уложились в 1 пт по обеим осям. У восьми дополнительных групп ЩГА2 проверены все 19 строк. Для двух строк на листе 28 границу ячейки по штриховой линии не удалось подтвердить автоматически. На изображении при 144 dpi обе строки целиком внутри ячейки. Остальные строки MTEXT прошли проверку границ автоматически.

Автоматическое сопоставление оставило четыре знака `=` на листе 19 ШС1 из-за близких точек вставки. На печати найдены четыре отдельных знака с теми же координатами в обеих ветках. Сдвиг каждого — 0 пт, изменение ширины — 0,017 пт. Проблемные подписи на листах 5, 14 и 18 повторно сопоставлены по символам и точкам вставки на печати. Сдвиг — 0 пт. Несопоставленных строк после разбора не осталось.

На листе 18 ШС1 в обеих ветках в итоговом DWG найдены 92 сплайна с восстановленным типом линии. На печати совпали все 17 738 векторных контуров, включая имеющуюся сплошную геометрию. На плане А2 размер бумаги сохранился после удаления из временного PDF метаданных измерительного масштаба, которые влияли на импорт AutoCAD.

## Эксплуатационные проверки

- На выборке `85,2-4` фактические вкладки DWG идут как `085`, `002`, `003`, `004`. Исходные номера в `report.json` и `complete.json.sheets` совпадают. С `--no-restore-dashes` счётчики восстановления отрезков, кривых и замечаний равны нулю.
- У повёрнутого CropBox видимый размер после нормализации — 800,25 × 600,10004 пт. Пакет содержит DWG и причину `plot_media_unavailable`. Окно показывает «Нужна сверка» с причиной и публикует один одноимённый DWG.
- После включения Rust по умолчанию повторены CLI и React для CropBox без переменной выбора экстрактора. Повтор CLI подтвердил кэш. Явный `--builder python` проверен отдельно на том же PDF.
- Регрессионный тест проверяет независимые точки вставки при обратном ходе текста и синтетическом пробеле, сохранение буквального пробела, а также выключение и включение обоих видов пунктира.

Переключение касается извлечения. Нормализацию, проверку и публикацию пока ведёт `convert.py`.
