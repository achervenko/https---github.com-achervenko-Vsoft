# Контрольные примеры универсального профиля

На этапе переноса расчётов Python остаётся эталоном поведения. Rust-модуль `universal_layout` получает номера листов и размеры видимой страницы в пунктах PDF с учётом поворота. Он возвращает размеры в миллиметрах, смещения импорта и модели, центры видовых экранов и имя носителя для печати. Порядок соответствует входному списку. Последовательные листы разделяют 2 дюйма при импорте и 20 мм в модели DWG.

Для проверки добавьте `--compare-layout` к запуску универсального профиля через `vsoft`. Python передаёт список объектов `{ "number": 1, "size_pt": [1684, 1191] }` на stdin внутренней команды `_plan-layout` и сравнивает полученный JSON со своей раскладкой до импорта и проверки кэша. Имена полей, порядок листов и носители должны совпадать. Допуск чисел в одинаковых единицах — `1e-8`. При расхождении выполнение прерывается с номером листа и именем поля. После успешного сравнения конвертация продолжится с выбранным сборщиком. По умолчанию DXF собирает Rust, с `--builder python` — Python.

## Подготовка PDF на Rust

Внутренняя команда `_prepare-pdf <исходный.pdf> <новый.pdf> [листы]` записывает страницы в заданном порядке и возвращает JSON с числом исходных страниц и массивом `pages`. Каждый элемент содержит исходный номер `number`, видимые размеры `size_pt` в пунктах PDF и поворот `rotation` в градусах.

Выполните команду в PowerShell из корня проекта, где находится `Cargo.toml`. В примере `source.pdf` лежит в корне, а `subset.pdf` создаётся при запуске.

```powershell
cargo run -- _prepare-pdf source.pdf subset.pdf '85,2-4'
```

Универсальный профиль со сборщиком Rust вызывает `_prepare-pdf` перед импортом. `convert.py` сверяет номера, размеры и поворот листов, затем нормализует поворот через PyMuPDF и сохраняет PDF для импорта в AutoCAD. Извлечение текста и штрихов остаётся на Python. При `--builder python` поднабор формирует PyMuPDF.

## Выбор сборщика

Из корня репозитория в PowerShell соберите VSoft:

```powershell
cargo build --locked --release
$pdf = 'C:\CAD\input.pdf'
.\target\release\vsoft.exe convert-result "$pdf" none "work/rust-builder-result" --profile universal
.\target\release\vsoft.exe convert-result "$pdf" none "work/python-builder-result" --profile universal --builder python
```

Универсальный профиль в CLI и React по умолчанию использует Rust-сборщик внутри `vsoft.exe`. Для отката в React задайте `$env:VSOFT_BUILDER = 'python'` перед `npm start`. Ключ Rust-пакета включает SHA-256 исполняемого файла и код Python-адаптера. Профиль EPLAN использует Python.

Для запуска React с профилем EPLAN используйте команды из корня репозитория:

```powershell
Remove-Item Env:VSOFT_BUILDER -ErrorAction SilentlyContinue
$env:VSOFT_PROFILE = 'eplan'
Set-Location desktop
npm start
```

React передаёт выбор сборщика только для универсального профиля. В режиме EPLAN окно использует Python и при установленной `VSOFT_BUILDER`.

При включённом восстановлении пунктира Python передаёт в JSON координаты обоих концов отрезка и точки начала штриха как целые числа в сотых долях пункта PDF. Например, координата `2.675` передаётся как `268`. Длины штрихов и промежутков передаются в пунктах PDF. Признак совпадения со сплошным ребром вычисляется по тем же целочисленным ключам. Rust округляет координаты импортированной геометрии по тому же правилу, сопоставляет ключи, добавляет типы линий и возвращает счётчики восстановления и сверки по листам. Применение типов выполняется до единственной записи DXF сборщиком. Флаг `--no-restore-dashes` отключает обработку в обеих ветках.

## Воспроизводимые примеры

В PowerShell из корня репозитория:

```powershell
python tests/make_universal_fixtures.py work/rust-universal-fixtures
$fixture = 'work/rust-universal-fixtures'
foreach ($name in 'mixed-iso', 'mixed-custom', 'stamp') {
    cargo run -- convert-result "$fixture/$name.pdf" none "$fixture/$name-result" --profile universal --compare-layout
    if ($LASTEXITCODE -ne 0) { throw "Ошибка конвертации $name" }
}
cargo run -- convert-result "$fixture/mixed-iso.pdf" none "$fixture/mixed-iso-reversed-result" --profile universal --compare-layout --pages 2,1
if ($LASTEXITCODE -ne 0) { throw "Ошибка конвертации в порядке 2,1" }
```

Успешное сравнение в каждом запуске подтверждает строка `Rust layout matches Python: … sheets` в stderr. Для обратного порядка дополнительно проверьте, что массив `sheets` в `mixed-iso-reversed-result/complete.json` равен `[2, 1]`.

| PDF | Что проверять |
|---|---|
| `mixed-iso.pdf` | Листы 1 и 2, альбомный А2 и книжный А3. Две вкладки в том же порядке, по одному прямоугольнику и одному объекту `TEXT` на лист. Контрольный PDF содержит обе страницы, статус `ready`. |
| `mixed-custom.pdf` | Лист 1 — А2, лист 2 после нормализации поворота — 600 × 1000 пт. По одному прямоугольнику и одному объекту `TEXT` на лист. Весь пакет без контрольного PDF, статус `needs_review`: лист 1 получает `plot_skipped_due_to_other_sheet`, лист 2 — `plot_media_unavailable`. |
| `stamp.pdf` | Три границы ячеек и три объекта `TEXT`. Контрольная печать содержит две горизонтальные и одну вертикальную надпись. Сравниваем ширину фрагментов вдоль строки и положения начала строки, допуск 2 пт. Надписи остаются внутри ячеек. |

## Локальные проектные примеры

- **План цеха Климовск, А2.** Вход 1684 × 1191 пт, вкладка примерно 594,08 × 420,16 мм. Контрольная печать 1684 × 1191 пт. В предыдущем экспорте на том же AutoCAD 2024 в модели были 1046 полилиний, 48 эллипсов, 16 окружностей, 6 дуг и один объект `TEXT` со знаком №.
- **ЩГА2, лист 85.** Запуск с `--profile eplan --pages 85` и локальным референсом. Вкладка A3, в штампе 85 из 103. В предыдущем прогоне статус `ready`, отчёт содержал 27 многострочных групп.

Проектные PDF и референс хранятся локально. Для сравнения сборщиков используем один и тот же AutoCAD и одну конфигурацию плоттера. Сравниваем вкладки, геометрию, текст и результаты проверки, поскольку хеш DWG может отличаться у эквивалентных чертежей.
