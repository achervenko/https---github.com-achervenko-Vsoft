# Архитектура VSoft

В штатном универсальном профиле (`--profile universal`) команда `vsoft` выбирает страницы в Rust. Rust записывает PDF-поднабор, а `convert.py` сверяет метаданные и нормализует поворот. AutoCAD импортирует геометрию из полученного `source.pdf`, а встроенный Rust-экстрактор извлекает из него текст и штрихи. Rust-сборщик получает эти данные и импортированный DXF, переводит геометрию из дюймов в миллиметры и создаёт вкладки в исходном бумажном масштабе. При `--builder python` универсальная сборка выполняется в [`universal.py`](../universal.py).

`plot_verify.inspect_universal()` сверяет размер печати с исходным листом с допуском 2 пункта, наличие геометрии и слов из извлекаемого текста. Профиль использует известные носители ISO A0–A4. Если хотя бы у одного листа нет подходящего формата, пакет публикуется с `preview_printed: false`. Листы без формата получают `plot_media_unavailable`, а остальные получают `plot_skipped_due_to_other_sheet`. Профиль и режим проверки входят в ключ кэша. Контракт публикации и подтверждения остаётся общим для обоих профилей.

Документ описывает текущий конвертер векторных PDF для Windows. Команды установки и запуска приведены в [README](../README.md).

## Контракт Rust → Python

Команда `vsoft convert …` ищет скрипт в таком порядке:

1. Если задана `VSOFT_ENGINE`, использует указанный файл. Неверное значение завершает команду.
2. Ищет `convert.py` в текущей папке. Это работает и для бинарника, скопированного за пределы репозитория.
3. Идёт вверх от папки бинарника. Подходит ближайшая папка, где есть и `Cargo.toml`, и `convert.py`.

Интерпретатор берётся из `VSOFT_PYTHON` или запускается по имени `python`. Rust передаёт путь скрипта первым аргументом, затем передаёт аргументы после `convert` по одному. Командная оболочка не используется. Текущая папка и стандартные потоки наследуются. Поэтому относительные пути к PDF, референсу, результату, скрипту и AutoCAD считаются от папки, из которой запущена команда. Сам Core Console позже запускается из временной папки.

| Ситуация | Код выхода |
|---|---|
| Вызов без аргументов, `-h` или `--help` | 0, выводится справка Rust. |
| Неизвестная подкоманда | 2. |
| Скрипт не найден или Python не запустился | 1, сообщение `vsoft:` в stderr. |
| Python запустился | Его исходный код через `std::process::exit`, включая 256 на Windows. Если код недоступен, возвращается 1. |
| Python отклонил аргументы, например страницы или `--acad` | 2 от argparse. |
| Пакет создан или кэш подтверждён | 0. Этот код возможен и при непустом `review`. |
| Ошибка выполнения Python | Ненулевой код. Отдельной стабильной нумерации по этапам нет. |
| Завершилась очередь | 1, если хотя бы один дочерний процесс вернул ненулевой код. Иначе 0. |

При `vsoft convert` Rust передаёт путь к своему бинарнику дочернему Python в служебной переменной `VSOFT_PAGE_SELECTOR`. Python открывает исходный PDF и вызывает `_select-pages <total> <max_digits>` у того же бинарника. `total` берётся из `len(doc)`, а `max_digits` из `sys.get_int_max_str_digits()`. Исходная строка `--pages` передаётся в stdin как UTF-8. Пустая строка и отсутствие параметра равнозначны.

Подкоманда возвращает JSON-массив номеров в stdout. Ошибка выбора даёт код 2 и объяснение в stderr, которое Python передаёт в `parser.error()`. Ошибка протокола или запуска останавливает конвертацию. При прямом запуске Python служебная переменная не нужна и используется `input_pages.py`.

Конвейер преобразования выполняет Python. Core Console импортирует PDF-геометрию, сохраняет DWG, запускает AUDIT и печатает вкладки.

## Конвейер конвертации

Для интерфейса есть отдельная команда `vsoft convert-result <pdf> <reference-dxf> <destination> [опции]`. Три пути идут перед опциями. Rust запускает тот же конвейер и создаёт для этого запуска отдельный временный каталог для подтверждения. Python пишет подтверждение под блокировкой папки результатов после публикации или при подтверждённом попадании в кэш.

При обработке задания stdout содержит один JSON-объект, а сообщения конвертера идут в stderr. Статусы: `ready` с путём `dwg`; `needs_review` с `dwg` и массивом `sheets` с полями `sheet` и `review`; `error` с исходным `exit_code`; `result_error` с `message`, если результат нельзя подтвердить. Оба успешных статуса возвращают 0, `result_error` возвращает 1, а `error` сохраняет исходный код. Обычный `vsoft convert` сохраняет текстовый вывод.

|---|---|---|---|
| Разбор запроса | `convert.py` и модуль выбора страниц на Rust или Python | Аргументы → разрешённые пути, открытый исходный PDF, выбор листов | Неподходящий путь `--acad`, ошибка открытия или чтения входных файлов, неверный выбор. Смотрите stderr. |
| Блокировка и кэш | `convert.py` | Пути и содержимое входных файлов → ключ кэша и блокировка папки | Папка занята другой задачей либо в быстром режиме уже есть `preview.pdf`. Подтверждённый кэш завершает команду с кодом 0. |
| Подготовка поднабора | `_prepare-pdf` записывает поднабор в штатной универсальной ветке. `convert.py` проверяет его и нормализует поворот. В Python-ветках `convert.py` сам создаёт поднабор. | Выбранные листы → временные `source.pdf`, `pages.json`, пустой `blank.dxf` R2018 | Неподходящий временный путь, размер или поворот страницы, отсутствие векторов, отсутствие текста в EPLAN или ошибка файла. | Публикация | `convert.py` | Проверенные временные файлы → файлы результата и затем `complete.json` | Ошибка вычисления SHA-256, копирования или замены файла. Без итогового маркера новый пакет не считается завершённым. |

В универсальном профиле Rust извлекает текст и штрихи через MuPDF, встроенную в `vsoft.exe`. Python пока нормализует страницы и управляет AutoCAD, проверкой и публикацией. Для сравнения явно задайте `VSOFT_PDF_EXTRACTOR=python`. Ошибка Rust-экстрактора останавливает запуск. Результаты сравнения приведены в [отчёте о приёмке](rust-extractor-acceptance.md).

Каждый запуск Core Console ограничен 300 секундами. Скрипты команд создаются во временной папке, а stdout и stderr записываются вместе в `<результат>/_work/<первые 12 символов ключа>/<этап>.log`. Для AUDIT код читает UTF-16 LE и ищет предусмотренные английские или русские строки о нуле ошибок.

В профиле EPLAN сборщик определяет принадлежность импортированной геометрии по X-смещению. Затем он размещает листы, восстанавливает пунктир по векторам исходного PDF, собирает надписи в `MTEXT` и заменяет исходный штамп и нижнюю часть рамки оформлением из референса. Он создаёт именованные группы листов и вкладки А3. Промежуточные DXF и отдельные PDF печати не публикуются.

## Выбор страниц

Нумерация начинается с единицы. Запятые разделяют элементы, `a-b` означает включительный диапазон по возрастанию. Пробелы по краям элементов допустимы, порядок запроса сохраняется. Дубли, обратные диапазоны, неверный синтаксис и номера вне PDF отклоняются.

| Вход для PDF из 103 страниц | Результат |
|---|---|
| Без `--pages` | `[1, 2, …, 103]`. Пустая строка также выбирает все страницы. |
| `85,2-4` | `[85, 2, 3, 4]`. |
| `2-4,3` | Дубль страницы 3, код выхода 2. |
| `104` | Номер вне PDF, код выхода 2. |

Для запроса `85,2-4` в поднаборе будут позиции 1–4. `pages.json` связывает их с номерами оригинала. Core Console импортирует страницы по позициям поднабора. Сборщик использует исходные номера в штампе, группах вроде `SHEET_085`, вкладках вроде `085` и записях отчёта. Печать идёт в порядке выбора. `total` содержит число страниц оригинала, поэтому первый выбранный лист имеет номер 85 из 103.

## Форматы JSON

Ни один из текущих форматов пока не содержит поля версии схемы.

### Входная очередь

Массив заданий. `pdf` и `destination` — обязательные строки с путями. `pages` — необязательная строка с синтаксисом `--pages`. Относительные пути считаются от папки JSON-файла. Генератор записывает абсолютные пути и дробит PDF на диапазоны.

```json
[{"pdf":"PDF input/drawing set.pdf","destination":"results/set/0085-0085","pages":"85"}]
```

### Временный `pages.json`

`numbers` — обязательный упорядоченный массив целых номеров исходных страниц, по одному на позицию поднабора. `total` — обязательное целое число страниц оригинала.

```json
{"numbers":[85,2,3,4],"total":103}
```

### Итоговый `report.json`

Массив записей по листам в порядке `numbers`. Все поля таблицы обязательны, кроме `plot_check`, которое добавляется только в полном режиме.

| Поле | Тип | Назначение |
|---|---|---|
| `sheet`, `title` | Целое, строка | Номер листа в оригинале и извлечённое название. |
| `geometry`, `excluded_footer` | Объекты «тип сущности → целое» | Счётчики перенесённой геометрии и импортированных элементов, отброшенных в зоне нижней части рамки. |
| `text_spans`, `multiline`, `logo_solids` | Целые | Количество перенесённых фрагментов текста, многострочных групп MTEXT и созданных заливок логотипа. |
| `dash_segments_restored`, `dash_curves_restored`, `dash_unmatched` | Целые | Сопоставленные прямые и кривые штриховые элементы и неподтверждённые совпадения. |
| `replacement_chars` | Целое | Количество U+FFFD в перенесённом исходном тексте. |
| `review` | Массив строк | Коды замечаний. Пустой массив означает, что выполненные проверки не дали флагов. |
| `plot_check` | Необязательный объект | `expected_words`, `missing_word_count` и `replacement_chars` — целые счётчики. `missing_words` и `missing_title_words` — объекты «слово → число недостающих вхождений» по всему листу и полю заголовка. |

```json
[{
  "sheet":85,"title":"Схема ПЛК","geometry":{"LINE":42},"text_spans":120,
  "logo_solids":0,"multiline":4,"dash_segments_restored":8,
  "dash_curves_restored":0,"dash_unmatched":0,"replacement_chars":0,
  "excluded_footer":{},"review":[],
  "plot_check":{"expected_words":100,"missing_word_count":0,"missing_words":{},
                "missing_title_words":{},"replacement_chars":0}
}]
```

### Итоговый `complete.json`

Обязательные поля: `key` — строка SHA-256 в шестнадцатеричной записи, `sheets` — упорядоченный массив целых, `total` — целое, `sha256` — объект «имя опубликованного файла → строка SHA-256», `preview_printed` — логическое значение. Маркер не содержит собственную контрольную сумму. В полном режиме в `sha256` добавляется `preview.pdf`. Ниже пример быстрого режима с сокращёнными хешами.

```json
{"key":"a1b2…","sheets":[85],"total":103,"sha256":{"drawing.dwg":"c3d4…","report.json":"e5f6…"},"preview_printed":false}
```

### Статус очереди

Для `queue.json` создаётся `queue.status.json`. Это массив записей о завершившихся дочерних процессах. Обязательны строки `pdf` и `destination` из задания и целое `exit_code`. Файл переписывается после каждого завершившегося процесса. После прерывания список может быть неполным или повреждённым, если запись не закончилась. При новом запуске очередь идёт с начала, а готовые пакеты пропускаются после собственной проверки кэша.

```json
[{"pdf":"PDF input/drawing set.pdf","destination":"results/set/0085-0085","exit_code":0}]
```

## Кэш, блокировка и публикация

Базовый ключ пакета — SHA-256 от байтов исходного PDF, DXF-референса при его наличии, UTF-8 JSON с настройками и содержимого `convert.py`, выбранного профильного модуля (`universal.py` или `build.py`), `plot_verify.py` и `input_pages.py`. Настройки записываются в порядке `[extractor, numbers, skip_preview, resolved_acad_path, profile, no_plot_media, trial_mtext]`. Путь к AutoCAD разрешается и проверяется до чтения кэша. В ключ входит путь к Core Console, а версия программы отдельно не учитывается.

При включённом восстановлении пунктира ключ дополнительно учитывает содержимое `universal_dashes.py`. Для Rust-сборки в него входят аргументы запуска сборщика после пути к бинарнику, SHA-256 самого бинарника и содержимое `universal_rust.py`. Если PDF-подготовщик запускается из другого бинарника, учитывается и его SHA-256. При выборе Rust-экстрактора дополнительно учитывается SHA-256 файла Arial.

`msvcrt.locking` устанавливает неблокирующую блокировку одного байта файла `_work/package.lock`. Дескриптор удерживается до выхода процесса. Сам файл может остаться после выхода. Под блокировкой скрипт сравнивает ключ и SHA-256 каждого требуемого файла со значениями в маркере. Отсутствующий, нечитаемый или несовпадающий маркер либо выходной файл приводят к новой сборке. Устаревший маркер удаляется перед сборкой. Действительный маркер подтверждает завершение, но не отсутствие флагов `review`.

Каждый проверенный файл копируется в папку назначения как `<имя>.pending` и затем заменяет итоговый файл. `complete.json` публикуется последним. Прерванный запуск может оставить логи, временную папку, старые или частично обновлённые результаты и файлы `.pending`. Замены атомарны для отдельных файлов, а не для всего пакета. Перед использованием пакета проверяйте наличие маркера и контрольные суммы. Повторный запуск пересоздаёт управляемые файлы при промахе кэша. Старые логи и посторонние файлы остаются.

После успешного выхода Python команда `convert-result` неблокирующе захватывает тот же первый байт перед чтением пакета. Rust удерживает блокировку до конца сверки маркера, отчёта, DWG и PDF печати. Если другой процесс уже занял папку, команда возвращает `result_error`. После завершения сверки блокировка освобождается. Путь из ответа не резервирует файл для последующего открытия.

## Проверки качества

| Объект и профиль | Что останавливает конвертацию | Что помечается для сверки |
|---|---|---|
| Исходный PDF, EPLAN | Поворот страницы, размер, отличный от 1127 × 762 пт, отсутствие извлекаемого текста или векторных рисунков. | — |
| Исходный PDF, универсальный | Отсутствие векторных рисунков. В штатной Rust-ветке также проверяются число и порядок страниц, исходный поворот и размеры, а после нормализации — нулевой поворот и сохранение видимого размера. | Отсутствие извлекаемого текста допускается. В отчёте такой лист получает `missing_text`. Растровые вставки отмечаются `raster_images_omitted`. |
| Собранный DXF, оба профиля | Порядок листов в отчёте отличается от запроса, число вкладок отличается от числа листов плюс Model или в группе листа нет подходящей геометрии вне слоя `LOGO`. | По счётчикам отчёта выставляются `missing_geometry`, `missing_text`, `unmapped_characters` и `dash_review`, если структурная проверка прошла. |
| Собранный DXF, EPLAN | Дополнительно проверяются число вставок в Model и наличие `MTEXT` на слое `TEXT` в каждой группе листа. | — |
| DWG, оба профиля | AutoCAD не открыл DWG или не подтвердил ноль ошибок `AUDIT`. | — |
| Контрольная печать, EPLAN | Печатный файл содержит не одну страницу, размер отличается от А3 более чем на 2 пт, отсутствует текст или геометрия либо номер листа и общее число листов в штампе не совпадают. | `plot_text_review` при пропущенных словах или U+FFFD и `plot_title_review` при пропущенных словах в названии. |
| Контрольная печать, универсальный | Печатный файл содержит не одну страницу, отсутствует геометрия или размер отличается от исходного более чем на 2 пт по любой стороне. | `plot_text_review` при пропущенных словах или U+FFFD. Если в пакете есть неподдерживаемый формат, печать пропускается с причинами `plot_media_unavailable` и `plot_skipped_due_to_other_sheet`. |

В универсальном профиле слова на печати сверяются с извлекаемым текстом исходного PDF. В EPLAN эталоном служит текст собранного DXF. Быстрый режим пропускает контрольную печать. Проверка слов не сравнивает положение надписей, а `AUDIT` проверяет целостность DWG. Геометрия поэлементно и электрические связи в штатной проверке не сравниваются.

## Перенос на Rust

В штатной универсальной ветке Rust выбирает страницы через `_select-pages`, записывает PDF-поднабор через `_prepare-pdf`, извлекает текст и штрихи из нормализованного `source.pdf` через `_extract-pdf` и собирает DXF через `_build-dxf`. При прямом запуске `convert.py` страницы выбирает Python. Python проверяет метаданные, нормализует поворот, управляет Core Console, кэшем, проверкой и публикацией. Сборка EPLAN выполняется в Python. Для универсального профиля `--builder python` возвращает Python-сборщик, а `VSOFT_PDF_EXTRACTOR=python` меняет только извлечение для Rust-сборщика. Подробности приведены в [контрольных примерах](rust-universal-baseline.md).

При переносе необходимо сохранить:

1. **CLI.** Аргументы и трактовку относительных путей, диагностику запуска, стандартные потоки и точную передачу кода дочернего процесса, пока Python остаётся движком.
2. **Нумерацию.** Выбор с единицы, порядок запроса, связь исходного номера с позицией поднабора и код 2 при ошибке выбора.
3. **Форматы и статусы.** Имена файлов, типы и смысл JSON-полей. Готовый пакет с замечаниями должен отличаться от ошибки выполнения. Изменение публичной схемы требует согласованного перехода потребителей.
4. **Кэш и публикацию.** Блокировку, проверку SHA-256 и запись маркера последним. При смене алгоритма ключа старые записи нужно явно считать несовместимыми.
5. **Качество.** Разницу полного и быстрого режимов, блокирующие ошибки и флаги. На одних и тех же векторных исходниках сверяйте порядок вкладок, текст, пунктир и отчёты. Универсальный перенос произвольной рамки потребует отдельного поведения и своих проверок.

Условия сбоя и прерывания сверены с кодом. Сценарии, выполненные на Windows, перечислены в разделе [«Проверено на Windows»](../README.md#проверено-на-windows).
