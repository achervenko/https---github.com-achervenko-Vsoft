# Пакетный перенос PDF в AutoCAD

Нужны Windows, AutoCAD 2024 с Core Console и Python с пакетами `pymupdf`, `ezdxf`, `Pillow`, `fonttools`. Скрипты выполняются локально без запроса к модели. Токены нужны для разбора исключений и визуальной сверки.

Для одного PDF: `python convert.py "C:\путь\проект.pdf" reference.dxf "C:\CAD\проект"`. Чтобы выбрать часть комплекта, добавьте `--pages 1-100`; следующий диапазон направьте в другой каталог. Используйте отдельную папку на каждый пакет. Имена PDF и папок результатов могут содержать кириллицу и пробелы. AutoCAD работает во временной папке с простым путём. Если системный TEMP содержит пробелы или кириллицу, задайте CAD_SCRATCH_DIR с существующим доступным путём без пробелов и кириллицы.

Для нескольких PDF: `python batch.py очередь.json reference.dxf`. Файл очереди — JSON-массив объектов с полями `pdf`, `destination` и необязательным `pages`, например `[{"pdf":"source.pdf","destination":"result","pages":"1-100"}]`. Порядок соответствует списку. Ошибка одного проекта не останавливает очередь. Результаты записываются в `очередь.status.json`.

В каждом успешном пакете есть DWG, PDF с печатью вкладок из AutoCAD, постраничный JSON и отметка о завершении. Повторный запуск с теми же файлами и настройками пропускает пакет после проверки SHA-256 всех результатов. При повреждении файла пакет собирается заново. Одновременная запись в одну папку блокируется. Рабочие логи хранятся в `_work`. Проверка контролирует открытие DWG, ошибки AUDIT, наличие геометрии в печати и перенос текста. Она не проверяет электрические связи, принадлежность всех строк к одному полю и точность оформления на каждом листе.

Текущая версия рассчитана на векторные листы EPLAN размером 1127 × 762 pt со штампом, как у ЩГА2. Другие форматы и сканы требуют отдельного профиля. Текст передаётся объектами MTEXT. Автоматическое объединение применяется к строкам одного исходного блока с одинаковым выравниванием, кеглем и регулярным межстрочным интервалом. Независимые надписи остаются отдельными объектами. Перед запуском нового шаблона проверьте выборку из схем, таблиц и крайних листов.

Для ЩГА2 проверка подсвечивает `dash_review`, когда часть штриховых контуров из PDF не удалось однозначно сопоставить с импортированной геометрией. Прямые участки восстанавливаются при совпадении координат. Отчёт содержит число восстановленных и неподтверждённых элементов. Пакет с этим флагом следует сверить с исходником перед выпуском.

Для большого архива `python make_queue.py C:\CAD\input C:\CAD\results C:\CAD\queue.json` сформирует очередь до 100 листов на DWG. Затем выполните `python batch.py C:\CAD\queue.json reference.dxf`. Выбор комплектов и диапазонов сохраняется в очереди, поэтому её можно проверить и отредактировать перед запуском.

Окно Windows запускается двойным щелчком по Start.cmd. Выберите PDF или папку, укажите папку результатов и нажмите «Конвертировать». В режиме папки каждый пакет содержит до 100 листов. Журнал показывает итог, а файлы report.json содержат список листов для ручной сверки. Для работы нужны установленные Python с указанными пакетами и AutoCAD 2024.


Быстрый режим: добавьте --skip-preview к convert.py или batch.py. Он сохраняет DWG и отчёт, повторно открывает DWG в AutoCAD для AUDIT и проверяет наличие текста и геометрии на каждом листе DXF. PDF не печатается, поэтому проверка печатного вида доступна в обычном режиме. DXF используется только как временный файл и не сохраняется в результатах. Для обычного и быстрого режима используйте разные папки результатов.


Обычный режим печатает все страницы и проверяет формат А3, номер и число листов в штампе, наличие графики и извлекаемого текста. В report.json есть plot_check с расхождениями текста DWG и печати и проверкой поля заголовка в штампе. Неверный номер или пустая страница останавливают выпуск пакета. Расхождения по тексту отправляются на сверку, поскольку при извлечении текста из PDF соседние надписи иногда сливаются. Эти проверки привязаны к текущему шаблону А3.
