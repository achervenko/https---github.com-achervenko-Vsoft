# VSoft

VSoft переносит векторные PDF с электросхемами в редактируемый AutoCAD DWG. Программа собирает геометрию, восстанавливает распознанный пунктир, переносит надписи в MTEXT и создаёт вкладку для каждого выбранного листа. Обработка выполняется локально, без OCR и облачных сервисов.

Сейчас поддерживается **профиль EPLAN ЩГА2**: страницы **1127 × 762 пункта PDF** без поворота, с извлекаемым текстом и векторной графикой. Сборщик заменяет исходный штамп и нижнюю часть рамки данными и оформлением из локального DXF-референса. Для других размеров, расположения полей штампа или правил сохранения рамок нужна адаптация профиля. ШС1 обрабатывался отдельной рабочей копией. Сканированные листы и повёрнутые страницы не поддерживаются. Надписи, превращённые в контуры в исходнике, остаются геометрией.

## Требования

| Компонент | Что нужно |
|---|---|
| Windows | 64-разрядная Windows с рабочим AutoCAD 2024. Конвертер использует блокировку файлов Windows. Проверено на Windows 11 x64. |
| AutoCAD | AutoCAD 2024 с Core Console (`accoreconsole.exe`). Для полной проверки нужен плоттер `DWG To PDF.pc3`. Сборщик использует шрифт `isocpeur.ttf` из папки шрифтов Windows. |
| Python | **3.11 или новее**. Код использует `hashlib.file_digest`, появившийся в 3.11. Проверено на **3.11.9**. |
| Пакеты Python | `PyMuPDF`, `ezdxf`, `Pillow`, `fonttools`. Версии в проверенном окружении: **2.1**, **1.4.5**, **13.0.0** и **4.68.0** соответственно. Минимальные версии пакетов отдельно не проверялись. |
| Окно через `Start.cmd` | Tkinter в установленном Python. |
| Окно на React | Node.js и npm. Проверенные версии указаны в разделе запуска окна на React. |
| Rust | Rust и Cargo с рабочим компоновщиком для Windows. Проверено на **1.100.0**, `x86_64-pc-windows-gnu`. В проекте используется редакция Rust 2021 и формат 4 для `Cargo.lock`. Более старые комплекты инструментов отдельно не проверялись. Готовому `vsoft.exe` Cargo не нужен. |
| Референс | Храните проектный `reference.dxf` локально. Он исключён из Git. В CLI его путь передаётся аргументом, а GUI ожидает этот файл в корне репозитория. |

## Быстрый старт

Все команды выполняйте **в PowerShell из корня репозитория**, где лежат `Cargo.toml`, `convert.py` и `Start.cmd`. Подставьте свои пути в начальном блоке. Пакеты установите в тот Python, которым будет пользоваться конвертер.

```powershell
python -m pip install PyMuPDF ezdxf Pillow fonttools

$fixture = 'C:\CAD\VSoft quick start'
$inputDir = Get-Item (Join-Path $fixture 'PDF input')
$pdf = Join-Path $inputDir.FullName 'drawing set.pdf'
$reference = (Resolve-Path .\reference.dxf).Path
```

В примере совместимый ЩГА2 PDF лежит в `PDF input` и содержит не меньше 85 страниц. Для более короткого файла укажите `--pages 1`. Папки результатов размещайте вне папки с входными PDF.

Запуск через Cargo:

```powershell
cargo run -- convert "$pdf" "$reference" "$fixture\rust run" --pages 85
```

Сборка и запуск релизного файла:

```powershell
cargo build --release
.\target\release\vsoft.exe convert "$pdf" "$reference" "$fixture\rust release" --pages 85
```

Прямой запуск Python в быстром режиме:

```powershell
python .\convert.py "$pdf" "$reference" "$fixture\python run" --pages 85 --skip-preview
```

Создание и запуск очереди:

```powershell
python .\make_queue.py "$($inputDir.FullName)" "$fixture\batch output" "$fixture\queue.json"
python .\batch.py "$fixture\queue.json" "$reference" --skip-preview
```

Генератор ищет PDF во вложенных папках. По умолчанию он создаёт пакеты по 100 листов. Параметр `--sheets-per-dwg` у `make_queue.py` принимает значения от 1 до 200. Для полной проверки печати уберите `--skip-preview` из команды `batch.py` и укажите отдельную папку результатов при создании очереди.

Запуск окна:

```powershell
.\Start.cmd
```

Выберите PDF или входную папку, укажите папку результатов и нажмите **Конвертировать**. В режиме папки оставьте поле **Листы** пустым. Окно использует стандартный путь к AutoCAD и полный режим проверки. Оно показывает журнал и итог выполнения процесса. Замечания по листам смотрите в `report.json`.

## Параметры запуска

| Параметр | По умолчанию | Поведение |
|---|---|---|
| `--pages` | Все страницы | Нумерация с единицы. Номера и включительные диапазоны разделяются запятыми. Порядок сохраняется. Дубли и номера вне PDF отклоняются. |
| `--acad` | `C:\Program Files\Autodesk\AutoCAD 2024\accoreconsole.exe` | Путь к файлу Core Console. Разрешается и проверяется до поиска в кэше. Доступен в команде для одного пакета. CLI очереди и окно его не принимают. |
| `--skip-preview` | Выключен | Пропускает печать и проверку печатного PDF. AutoCAD AUDIT и проверки собранного DXF выполняются. Используйте отдельную папку для быстрого режима. |
| `VSOFT_ENGINE` | Не задана | Переопределяет путь к `convert.py` для Rust. Неверный путь останавливает запуск. Относительный путь считается от текущей папки. |
| `VSOFT_PYTHON` | `python` | Имя исполняемого файла в PATH или путь к нему. При присваивании укажите сам путь, без кавычек внутри значения и без дополнительных аргументов. |
| `CAD_SCRATCH_DIR` | Системный временный каталог Python | Существующая доступная для записи папка для временных файлов AutoCAD. Разрешённый путь должен состоять из ASCII и не содержать пробельных символов. Входной PDF и папка результатов могут содержать пробелы и кириллицу. |

Для каждого источника и диапазона используйте отдельную папку результатов. Новый запуск с изменёнными настройками может заменить предыдущие выходные файлы. Быстрый режим отклоняет папку, в которой уже есть `preview.pdf`.

Для PDF из 103 страниц:

| `--pages` | Результат |
|---|---|
| Не задан | Все страницы с 1 по 103 в порядке оригинала. |
| `85,2-4` | Страницы 85, 2, 3, 4 в указанном порядке. |
| `2-4,3` | Дубль страницы 3, код выхода 2. |
| `104` | За пределами PDF, код выхода 2. |

## Результаты и диагностика

### Окно VSoft на React

Первая версия окна запускается из исходников. Сборка проверена в Windows с Node.js 24 и npm 11. Для конвертации по-прежнему нужны Python с зависимостями, AutoCAD 2024 Core Console и `reference.dxf` в корне проекта.

В PowerShell из корня репозитория выполните:

```powershell
cargo build --release
Set-Location desktop
npm ci
npm start
```

Перетащите PDF или папку в окно, выберите папку результатов и запустите конвертацию. Для одного PDF можно указать листы. При обработке целого PDF окно разбивает его на пакеты до 100 листов. По каждому пакету виден результат проверки. Если нужна сверка, окно показывает номера листов и причины.

- **Полный режим** сохраняет `drawing.dwg`, `preview.pdf`, `report.json` и `complete.json`.
- **Быстрый режим** сохраняет `drawing.dwg`, `report.json` и `complete.json`. DXF в обоих режимах используется как промежуточный файл.
- **`complete.json`** записывается последним и содержит SHA-256 опубликованных файлов. Наличие одного DWG не подтверждает, что пакет завершился. При повторе программа проверяет ключ и контрольные суммы.
- В **`report.json`** есть запись на каждый выбранный лист. Непустой список `review` означает, что пакет создан и лист требует сверки. Код выхода при этом может быть 0. Файл статуса очереди содержит только коды процессов, поэтому замечания ищите в отчётах пакетов.
- Логи `import.log`, `save.log`, `audit.log` и `plot.log` ищите в **`_work/<первые 12 символов ключа>`** внутри папки результата. Если лог этапа ещё не появился, смотрите сообщение в терминале. Для `queue.json` статус сохраняется рядом в `queue.status.json`.

См. [архитектуру](docs/architecture.md): этапы, контракты файлов и границы проверок.

## Проверено на Windows

Команды через Cargo, релизный `.exe` и прямой Python обработали лист 85 ЩГА2. Во входных и выходных путях были пробелы. Команда Rust сохранила порядок `85,2,3,4` в `complete.json` и передала код Python **256** без изменения. Дубли и номер за пределами PDF проверены через CLI. Выбор всех страниц без `--pages` проверен на уровне функции разбора. Команды очереди из этого README обработали все 103 листа в быстром режиме двумя пакетами: 100 и 3 листа. Оба завершились с кодом 0. `Start.cmd` открыл окно. Сценарий нажатия кнопок в GUI сверялся по коду.
